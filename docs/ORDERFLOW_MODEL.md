# 订单流力竭模型 V2

## 边界

本实现对应原作者材料中的共同逻辑，而不是旧代码的 EMA 偏离或 Renko 连砖反转。
Renko/Trend Reversal 图可用于人工观察位置，但量化信号必须从原始成交回答两个问题：

1. 市场是否到了值得反转的位置？
2. 主动买卖投入很大时，价格是否已经推不动？

只有位置、力竭与反向确认形成顺序证据链，模型才提高仓位。

## 特征

逐笔成交按 60 秒聚合 OHLC、成交额和主动成交 Delta。滚动基线使用此前 60 个桶的
成交额中位数；位置看此前 90 个桶的高低点及 UTC 日内 VWAP。

- `volume_ratio = 当前成交额 / 历史成交额中位数`
- `delta_share = 主动买卖净额 / 成交额`
- `efficiency = |close - open| / (high - low)`
- 扫前高：创新高后收回前高下方；扫前低对称
- 订单簿：中间价 ±0.2% 的 bid/ask 名义额失衡
- OI：相邻公共 OI 快照的名义额变化

生产配置要求先扫过并收回此前 90 分钟高点/低点；VWAP 只做展示，不单独授权逆势。
吸收候选还要求 `volume_ratio ≥ 2.0`、`|delta_share| ≥ 0.15`，同时
`efficiency ≤ 0.35` 或价格直接逆着主动成交方向收盘。参数集中在
`config/strategy-final.toml`，不要在代码中散落隐藏阈值。

## 三类入场

| 阶段 | 条件 | 风险预算 |
|---|---|---:|
| 极值试仓 | 位置 + 主动成交力竭 | 35% |
| Delta 确认 | 6 个桶内 Delta 翻转且价格离开力竭区 | 100% |
| 二次失败 | 确认后 10 个桶内，同一区域再次进攻失败 | 50% |

三类阶段可分别启停；生产配置以逐笔样本外结果决定实际执行阶段。

当前引擎是单净仓模式：已有持仓时不会把确认信号当作另一套策略重新开仓。因此阶段贡献
代表实际开仓时所处阶段，而不是把同一笔仓位重复归因三次。

## 风险与退出

- 初始止损放在扫流动性的针尖之外，再留 3.5 bps 缓冲。
- 止损距离小于 0.3% 时扩到 0.3%，大于 0.6% 时跳过，防止仓位公式失真。
- 仓位为 `equity × risk_pct × stage_scale / |entry - stop|`，同时受
  `max_risk_pct`、数量步长和最小名义价值约束。
- 名义仓位同时封顶为账户权益的 3 倍，与默认实盘杠杆一致。
- TP1 = 2R，平原始仓位 50%，随后止损移至入场价。
- TP2 = 4R，再平原始仓位 25%。
- 剩余 25% 使用 0.6% 单向收紧的 runner stop。
- 4 小时仍未结束则时间止损全平。
- 日连损/日回撤由引擎熔断器控制。

`closed_frac` 按原始仓位口径只由账户成交层维护。引擎不得在收到部分平仓动作后再次
累加，否则 TP2 会被错误判定为已经完成。

## 数据与诚实性

- 实时成交、订单簿和 OI 均来自 Binance 主网公共接口；paper 订单才发往 Demo。
- 不用 5m/1h K 线模拟逐笔方向或成交量。
- 默认启动约 20 分钟后形成最小真实成交基线，60 分钟后滚动基线完整；前端明确显示进度。
- 回测缺少历史订单簿时，book 特征为空而不是伪造；核心成交 + OI 逻辑仍可验证。
- 任何“20%+”都只能是实验目标，不是收益承诺。上线依据应包括样本外交易数、费用后
  收益、最大回撤、阶段归因和参数邻域稳定性。
