# TRDR 市场地图 + 订单流力竭模型 V5

## 模型边界

本实现直接消费 Binance、Bybit、OKX 主网现货/永续逐笔成交与盘口，不用 K 线或 Renko
砖伪造 Delta，也不依赖 TRDR 私有接口。
自动化链条为：

`TRDR 流动性位置 → 跨市场 Delta/OI/趋势 → 10 秒力竭 → 3/5 分钟反转 → context 分层 → 结构风控`

## TRDR 上游市场地图

- 每 5 秒读取三家交易所的现货和永续深度（Binance/Bybit 1000 档、OKX books-full），
  计算现价上下 1%、2.5%、5% 的买卖名义金额比例，并按 green/yellow/red/blue 分级。
- 从主导方向的真实价格档位中寻找最强挂单墙，记录区域上下沿、距现价、持续时间、深度
  覆盖以及现货/合约是否同向。生产入场最低要求 yellow、距现价不超过 0.4%、色带持续
  30 秒、至少 4 个完整盘口，且至少 2 家现货和 2 家永续同向。
- 同时聚合六路逐笔成交的 30 分钟主动成交 Delta，直接使用全市场美元档位，不再按
  Binance 覆盖率估算。逐笔成交按 $10 价格格聚合 footprint，记录最强簇和连续失衡档位。
- Binance、Bybit、OKX 强平事件统一为多头/空头被强平金额，并在同一 30 分钟窗口累计。
- OKX 合约面值启动时从 instruments API 动态读取，只有接口故障时才使用回退规格。
- 永续 OI 与 Delta 组成新多、新空、空头回补、多头平仓四种状态；30 分钟收益与路径效率
  判定 range/trend_up/trend_down。上涨趋势禁止逆势做空，下跌趋势禁止逆势做多。
- 这一层不下单；现货数据只用于上下文，不建立现货仓位。

Discord 的五个信号频道不是五套相互独立的策略，而是同一事件通过不同过滤强度后的
质量层级。一个事件只归入最高通过层级；同一事件簇不会重复下单。

## 放量事件

逐笔成交按 10 秒聚合 OHLC、成交额和主动成交 Delta。此前 360 个桶（1 小时）的成交额
中位数构成自适应基线，避免把某个固定美元阈值写死到不同波动环境中。

- `volume_ratio = 当前 10 秒成交额 / 1 小时成交额中位数`
- `delta_share = 主动买卖净额 / 当前成交额`
- `efficiency = |close - open| / (high - low)`
- 经典候选要求量比至少 1.6、`|delta_share|` 至少 0.15，并且价格效率不高或直接逆着
  主动成交方向收盘。
- 量比至少 2.2 或 `|delta_share|` 至少 0.35 时记为强事件，否则记为弱事件。

放量只建立待确认事件，不会下单。强事件在 3 分钟内等待 Delta 和价格同时反转；弱事件
使用 5 分钟窗口。超时明确记录为 `expired`。

## Context 与五层归因

Context 最多 8 分：TRDR 位置、明显吸收、跨市场 Delta、footprint、OI、现货/合约盘口
共振、局部扫高低点或 VWAP 偏离、强平各 1 分。生产配置强制满足位置、区域持续时间、
盘口共振、逐笔来源覆盖、Delta 方向和 footprint 连续失衡；局部位置和强平只作为加分项。

| 层级 | 规则 | 生产执行 |
|---|---|---|
| 经典力竭 | 基础事件得到 Delta 确认 | 观察 |
| 强弱确认 | 强事件确认，但 context 不足 | 观察 |
| 多因子高频 | 至少 1 个 context 因子 | 观察 |
| 多因子均衡 | 全部生产门槛、context ≥ 6、量比 < 2.5 | 真实执行，60% 风险系数 |
| 多因子高质 | 强事件、全部生产门槛、context ≥ 7、量比 ≥ 3.0 | 真实执行，80% 风险系数 |

量比 2.5～3.0 的噪声夹层会归入高频观察层，不会绕道进入均衡执行。确认后的事件簇冷却
10 分钟，修复同一次放量连续报警和重复入场的问题。

经典、强弱和高频层继续做影子观察；均衡与高质层实际执行。前端展示所有事件、硬门槛、
淘汰原因和层级，方便模拟盘积累独立样本。

## 入场与退出

- Delta 确认后在原放量区挂被动限价，10 分钟未回踩则撤销，不追价。
- 止损放在放量桶极值之外并留 3.5 bps 缓冲；最小止损距离 0.5%，最大 1.0%。
- 均衡仓位风险系数 0.60，高质层 0.80；二者均受账户风险上限、数量步长和最大杠杆约束。
- TP1 为 1.5R，平原始仓位 50% 并移到保本；TP2 为 3R，再平 25%。
- 剩余 25% 使用 0.6% 单向移动止损；4 小时全部平仓。

0.5% 止损不是增加风险金额，仓位会相应缩小。它修复了旧 0.3% 止损在信号兑现前频繁被
噪声扫掉的问题。

## 历史基线（V3，不代表 V5 结果）

使用本地 Binance Futures 逐笔数据、真实手续费和同一账户占仓约束：

- 2026-06-01～06-30：88 回合，胜率 53.4%，PF 1.26，手续费后每笔 +$16.37，
  最大回撤 1.0%。
- 2026-05-01～05-31：45 回合，胜率 31.1%，PF 0.45，手续费后每笔 -$40.14，
  最大回撤 1.8%。

以上结果来自未接入 TRDR 地图的 V3，只能作为对照，不能当作 V5 收益。V5 需要重新回测
并在模拟盘积累独立样本；任何 20% 目标都不能替代样本外收益、回撤和费用验证。

## 数据与可观测性

- 模拟盘/实盘信号来自三所主网六路逐笔成交与盘口、三路永续 OI 和三路强平；Demo 只负责
  Binance 合约撮合。
- 前端分开展示 TRDR 地图与放量、Delta 压力、价格停滞、待确认、最终层级五步漏斗。
- 市场地图日志包含各深度带、实际墙体区域、源覆盖、跨市场 Delta、OI 象限、趋势和限制；
  入场日志会固化当时引用的地图字段，便于事后判断是地图、确认还是执行层失效。
- 每个 10 秒市场地图快照同时记录六路交易所各自的成交额、净 Delta、Delta 占比，以及
  三家永续各自的多头/空头强平金额；确认信号会固化这些贡献数据，避免总数异常时无法
  追溯到具体数据源。
- 六个盘口分别记录快照年龄、档位数、上下覆盖范围，以及 ±1%/±2.5%/±5% 各带的买卖
  挂单金额和深度完整性，便于定位“覆盖不足”来自哪个交易所或哪个价格带。
- 每条评估包含量比、成交速率、Delta、context 分数、确认截止时间及去重/过期原因。
- Live Journal 仅保留最近 300 条评估快照，避免 10 秒评估长期撑大前端文件。
- 每次启动拥有独立 `run_id`，全量评估写入 `data/evals/<mode>/<run_id>.jsonl`；记录
  `strategy_hash`、Git commit 和运行模式，避免不同版本的样本混在一起。
- 可研究事件按 UTC 日期追加到 `data/research/<mode>/YYYY-MM-DD.jsonl`。其中包含完整配置
  快照、confirmed 信号原始载荷，以及订单的 intent/accepted/filled/rejected/expired/canceled
  生命周期；交易所成交保留 `order_id` 和 `trade_id`。
- 所有 confirmed 信号都会做影子追踪，包括禁止交易的观察层。在 5/15/30/60/120/240
  分钟记录方向收益、MFE、MAE，并按配置的往返费用估算净收益。这是判断“过滤器筛掉了
  alpha”还是“观察层本来就无效”的主要数据，不能把影子收益当作真实账户收益。
- Journal 中会持久化尚未走完 240 分钟的影子信号，正常重启后继续跟踪；日志是 append-only，
  部署时应与 journal 一起备份。
