# 订单流力竭模型 V3

## 模型边界

本实现直接消费 Binance 主网逐笔成交，不用 K 线或 Renko 砖伪造 Delta。自动化链条为：

`10 秒放量事件 → 主动成交推不动价格 → 3/5 分钟 Delta 反转 → context 分层 → 结构风控`

Discord 的五个信号频道不是五套相互独立的策略，而是同一事件通过不同过滤强度后的
质量层级。一个事件只归入最高通过层级；同一事件簇不会重复下单。

## 放量事件

逐笔成交按 10 秒聚合 OHLC、成交额和主动成交 Delta。此前 360 个桶（1 小时）的成交额
中位数构成自适应基线，避免把某个固定美元阈值写死到不同波动环境中。

- `volume_ratio = 当前 10 秒成交额 / 1 小时成交额中位数`
- `delta_share = 主动买卖净额 / 当前成交额`
- `efficiency = |close - open| / (high - low)`
- 经典候选要求量比至少 1.6、`|delta_share|` 至少 0.15，并且价格效率不高或直接逆着
  主动成交方向收盘。
- 量比至少 2.2 或 `|delta_share|` 至少 0.35 时记为强事件，否则记为弱事件。

放量只建立待确认事件，不会下单。强事件在 3 分钟内等待 Delta 和价格同时反转；弱事件
使用 5 分钟窗口。超时明确记录为 `expired`。

## Context 与五层归因

Context 最多 4 分：关键位置、明显吸收、订单簿支持、OI 异动各 1 分。关键位置来自此前
90 分钟高低点的扫出收回，或日内 VWAP 至少 0.3% 的方向性偏离。

| 层级 | 规则 | 生产执行 |
|---|---|---|
| 经典力竭 | 基础事件得到 Delta 确认 | 观察 |
| 强弱确认 | 强事件确认，但 context 不足 | 观察 |
| 多因子高频 | 至少 1 个 context 因子 | 观察 |
| 多因子均衡 | 必须有关键位置、context ≥ 3、量比 < 2.5 | 真实执行，60% 风险系数 |
| 多因子高质 | 必须有关键位置、context ≥ 3、量比 ≥ 3.0 | 观察 |

量比 2.5～3.0 的噪声夹层会归入高频观察层，不会绕道进入均衡执行。确认后的事件簇冷却
10 分钟，修复同一次放量连续报警和重复入场的问题。

只执行均衡层是当前样本验证结果，不代表其他层永久无效。前端仍展示所有事件、淘汰原因
和层级，方便模拟盘继续积累独立样本。

## 入场与退出

- Delta 确认后在原放量区挂被动限价，10 分钟未回踩则撤销，不追价。
- 止损放在放量桶极值之外并留 3.5 bps 缓冲；最小止损距离 0.5%，最大 1.0%。
- 仓位为 `equity × risk_pct × 0.60 / |entry - stop|`，并受账户风险上限、数量步长和
  最大杠杆约束。
- TP1 为 1.5R，平原始仓位 50% 并移到保本；TP2 为 3R，再平 25%。
- 剩余 25% 使用 0.6% 单向移动止损；4 小时全部平仓。

0.5% 止损不是增加风险金额，仓位会相应缩小。它修复了旧 0.3% 止损在信号兑现前频繁被
噪声扫掉的问题。

## 已完成验证

使用本地 Binance Futures 逐笔数据、真实手续费和同一账户占仓约束：

- 2026-06-01～06-30：88 回合，胜率 53.4%，PF 1.26，手续费后每笔 +$16.37，
  最大回撤 1.0%。
- 2026-05-01～05-31：45 回合，胜率 31.1%，PF 0.45，手续费后每笔 -$40.14，
  最大回撤 1.8%。

因此当前模型适合模拟盘验证，不具备跨环境稳定盈利的证据。6 月结果不能被描述为收益
承诺；5 月样本外失败必须保留在结论中。后续应依据模拟盘新增样本研究市场状态过滤，而
不是继续在同一历史区间搜索参数。

## 数据与可观测性

- 模拟盘/实盘信号都来自主网公共逐笔成交、订单簿和 OI；Demo 只负责订单撮合。
- 前端展示放量、Delta 压力、价格停滞、待确认、最终层级五步漏斗。
- 每条评估包含量比、成交速率、Delta、context 分数、确认截止时间及去重/过期原因。
- Live Journal 仅保留最近 300 条评估快照，避免 10 秒评估长期撑大前端文件。
- 每次启动拥有独立 `run_id`，全量评估写入 `data/evals/<mode>/<run_id>.jsonl`；记录
  `strategy_hash`、Git commit 和运行模式，避免不同版本的样本混在一起。
- 可研究事件按 UTC 日期追加到 `data/research/<mode>/YYYY-MM-DD.jsonl`。其中包含完整配置
  快照、confirmed 信号原始载荷，以及订单的 intent/accepted/filled/rejected/expired/canceled
  生命周期；交易所成交保留 `order_id` 和 `trade_id`。
- 所有 confirmed 信号都会做影子追踪，包括禁止交易的观察层。在 5/15/30/60/120/240
  分钟记录方向收益、MFE、MAE，并按配置的往返费用估算净收益。这是判断“过滤器筛掉了
  alpha”还是“观察层本来就无效”的主要数据，不能把影子收益当作真实账户收益。
- Journal 中会持久化尚未走完 240 分钟的影子信号，正常重启后继续跟踪；日志是 append-only，
  部署时应与 journal 一起备份。
